# 我的目标：2026 聚光灯 21 天游戏创作挑战

以既有 PvZ-Infinite 的设计构想为基础，用 ChatGPT 聊天协作推进设计、代码、测试和资料整理；在正式主题公布后的开发期内，完成原创、可玩的安卓游戏，确保可在 TapPlay 运行、通过审核并有效投稿。

当前交付：2.5D 斜俯视＋可旋转调整视角＋离线单机。持久农场、360°防守、昼夜与成长是设计方向；正式主题、最小玩法规模和公开名称尚待落地，不把整个长期大作一次做完。

更新时间：2026-09-07；北京时间 UTC+8（与新加坡时间相同）。

完成的标准不是“代码写好”或“能导出APK”，而是正式游戏能玩、TapPlay与平台检测通过、展示及声明齐全，并在截止前通过审核、完成平台活动投稿；另按全程参与奖条件留足公开日志与有效试玩。

规则整理基线：2026-09-05；本页更新：2026-09-07。赛程与平台文档已部分复核，奖项页及部分展开细则本轮访问受限；详见来源状态。此页不是官方资格认定。

## 01 · 我的作品范围

模块虽然叫 AI 3D 实验室，本次目标不要求完整3D。以下分清已确认方向、当前建议和长期保留项。

| 状态 | 本次范围 |
| --- | --- |
| 用户已确认 | 安卓游戏；2.5D斜俯视；可转动观察方向；以ChatGPT聊天作为主要协作入口。 |
| 原构想保留 | 持久农场、白天建设/夜晚防守、360°来敌、植物成长和玩家参与；活着的资产跨夜保留，不把家园每晚清零。 |
| 建议的最小闭环 | 建设/种植 → 夜间防守 → 黎明结算 → 带着存活资产进入下一天。数量、节奏、卡牌与变异规模在开题后收敛。 |
| 本届不做联网玩法 | 合作、PvP、在线交易、云排行榜和运行时调用云端GPT均不进入参赛包；世界观中的“意识上传”可在本地模拟。 |
| 当前不承担，不是永久删除 | 完整3D、第一/第三人称、大世界、复杂载具/机甲、庞大科技树。长期GDD与历史构想继续保留。 |

## 05 · AI、第三方素材与公平边界

AI可作为设计和开发工具，但不替代授权、原创性和真实过程记录。公平问题不再额外咨询；用来源、版本和真实日志保护自己的作品。

| 事项 | 执行边界 |
| --- | --- |
| AI资产声明 | 使用AI生成的游戏资产时，在游戏介绍中明确标注“本游戏内含有使用 AI 生成的游戏资产”，随投稿说明具体内容和比例。 |
| 奖项影响 | 按已整理的细则，未按要求披露会失去全部奖项评选资格；AI美术资产占比达到“50%以上”不参评最佳美术奖，不等于全部奖项都不能参赛。占比如何核算需如实注明。 |
| 第三方资产 | 记录文件、作者/来源、许可、用途、修改和数量/比例；免费不代表可商用，AI生成不自动消除相似IP风险。 |
| 代码与图片分开记 | AI辅助代码另记工具和范围，不用代码行数混算美术资产占比；源代码、模型、音效、图片各有来源台账。 |
| 赛前准备与正式创作分开 | 9月android-lab是练习区；正式工程在开题后按主题制作。复用任何准备材料都应留出处，不修改历史日期、不伪造制作时长。已有构想的资格不作保证。 |
| 既有作品边界 | 规则将使用过往作品列为违规异议情形；允许合法素材复用不能被解释为旧游戏直接参赛。不会通过重命名/删除历史来掩盖。 |
| 可选奖项 | 当前优先安卓，不默认已满足双端奖；Godot路线不默认满足“全程使用TapTap制造”的专属奖条件。其他奖项只按届时实际条件申请。 |

## 06 · 安卓物料提交清单

把宣传图、宣传片、实机录屏和开发日志分开准备；最终以后台实际必填项目及官方最新版规格为准。

| 物料 | 关键规格与内容 | 性质 |
| --- | --- | --- |
| 游戏图标 | ≥512×512；PNG/JPG；直角方图，不自行裁圆角；不使用默认、白底、黑底或透明底图标。 | 平台必填 |
| 16:9宣传图 | ≥1920×1080；PNG/JPG；≤4MB；清楚展示游戏名，不加其他宣传文字；不用未排版截图或简单拼贴。 | 平台必填 |
| 真实游戏截图 | 至少3张不重复；方向和比例一致；横图≥1280×720、竖图≥720×1280；每张≤4MB；真实玩法在前，不能用概念图代替。 | 平台必填 |
| 实机录屏 | MP4/MOV；H.264/H.265；>15秒且≤30分钟，建议≤2分钟；短边≥540px，≤5GB；前5秒进入玩法，连续核心玩法>10秒。 | 开放下载/试玩必填 |
| 录屏内容限制 | 不额外加配音/字幕，不拍设备外观；无其他平台水印/导流，不用纯CG或宣传片替代实际玩法；录屏画面占比≥80%。 | 录屏审核要求 |
| 简介与版本更新日志 | 简介讲玩法，更新日志讲本次版本变化；提供简体中文，安装后App名与商店标题一致；不塞联系方式/群号或违规外链。 | 平台必填 |
| 开发者的话 | 写设计理念和制作经历，与简介区分；不写未实现功能，不承诺未经测试的帧率。 | 建议准备 |
| 讲解视频/宣传片 | 单独准备，不拿它替代实机录屏；宣传片≥15秒、≥1280×720、16:9、MP4/MOV，展示已有玩法。 | 按赛事/后台要求准备 |
| AI及第三方素材说明 | 具体资产、来源/许可、AI生成范围与比例；留授权证明及自己的统计口径。 | 涉及使用时必备 |
| 公开开发日志 | 至少5篇的额外奖项材料，带实际截图/短视频、指定标签和发布链接；不是商店里的版本更新日志。 | 全程参与奖额外 |

## 07 · 聊天协作 → 工程 → TapPlay → 有效投稿

继续用ChatGPT聊天推进，不要求为了交流先学命令行。代码完整工程和版本证据在项目仓库维护；有权限的工具实际执行，没有完成的操作明确留空。

| 阶段 | 验收产物 / 分工 |
| --- | --- |
| 需求和计划 | 用户决定核心体验；AI按既有GDD收敛范围，明确已确认与建议；工具费用先用现有额度，不擅自新增付费订阅。 |
| 实现与版本 | Godot/GDScript完整工程，GitHub保存真实提交；实验目前固定Godot4.5.2，不因通用教程提到新版本就直接升级。 |
| 构建与自动测试 | 重复构建APK、解析检查、坐标/触控/存档/遮挡/性能回归；留源码SHA、构建ID和安装包校验值。 |
| 真实安卓设备 | 安装、物理多指、不同屏幕安全区、返回键、切后台、杀进程后恢复、持续运行与发热。用户暂忙，不据此停止独立工程工作。 |
| TapPlay实际环境 | 按官方后台开启/测试；独立核查启动和存档，普通安装版存档与TapPlay不互通。自动检测成功不代替手动体验，模拟器不代替TapPlay。 |
| 账号与签名安全 | 本人完成身份认证及必须的授权；正式密钥安全保存和备份，不进聊天/公开仓库。临时调试签名不能直接视为最终上架签名。 |
| 审核与提交 | 先平台提审，修复退回项，再确认平台活动投稿。APP、素材、日志和最终版本一致，保留回执。 |
| 赛后试玩与复盘 | 记录平台有效试玩、问题和迭代；复盘源码、成本、日志和实际结果。工具链成功不等于比赛获奖。 |
