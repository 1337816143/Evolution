## 07 · Three.js 柔性热敏纸小票

创建 Three.js + WebGL 交互热敏纸小票，不是平面 CSS 摆动动画。白色背景、轻微阴影，小票印有原创幽默的图形学购物清单。
实现粒子网格与 Verlet/PBD 或 XPBD，包含结构、剪切及弯曲约束。顶部整行粒子的逆质量为 0，固定到同一条水平直线；每个子步/求解后再次保证固定边，不许只固定左中右 3 点，不许出现晾衣绳下垂。
下半部可柔软形变，鼠标和触屏可抓取局部、拖动和弯曲，松手后自然回弹。使用指针捕获、射线与拖拽平面、受限拉力；拖出窗口、双指和取消事件不能造成爆炸或永久卡住。
纸张应较抗拉伸但可弯曲；材质像热敏纸而非布、塑料或金属。双面渲染需检查背面文字与透明排序。
明确区分暂时折弯与永久折痕：持续折痕需要静止角/塑性规则；自碰撞若未实现必须列为限制，不能仅靠 Verlet 声称真实折纸。
采用固定时间步、有限子步与迭代数、后台暂停及像素比上限。网格密度和迭代次数须由实测决定。提供重置与暂停按钮，处理窗口缩放。
优先给可复现 npm/Vite 工程和锁文件；若给单 HTML，说明外部 CDN/联网/本地 HTTP 要求，不能承诺任意 file:// 双击运行。
先解释方案，再完整实现并测试：整条顶边误差、极端拖动、30 秒静置、重置、手机触控、控制台错误及帧时间。60 FPS 只是目标，不得捏造测量结果。

## 08 · MCP 连接故障定位

当前目标：[Blender / Godot]；系统：[填写]；客户端：[填写]；错误日志：[脱敏粘贴]。
先判断客户端运行在本机、WSL、容器还是云端。localhost 指向该进程所在主机，不能把云端 localhost 当作我的电脑。
只读取必要的版本、命令解析路径、MCP 配置和目标端口状态，不导出环境变量全集或密钥。
按顺序检查：命令能否独立解析；GUI 是否刷新 PATH；uvx/npx/Node 的实际路径；Godot 可执行文件路径；Blender 插件启用与服务启动；端口冲突；stdio 是否有非协议日志；客户端超时。
Codex 使用 TOML，不能直接粘贴 Claude 的 mcpServers JSON。Windows PowerShell 使用 Get-Command 或 where.exe 查路径；必要时使用绝对路径，解释 .cmd 与可执行文件区别。
同一时间只保留必要的客户端/服务实例。不要为排障关闭全部防火墙、监听 0.0.0.0 或将未鉴权 MCP 暴露公网。
给出一个最小修改并复测；成功后记录版本和配置。失败就报告已排除项、仍缺的证据，不连续重装整套软件。

## 09 · 性能测量与预算

请对当前真实可运行工程进行性能验收：[工程/构建路径]。
先记录设备、CPU/GPU、内存、系统、引擎/浏览器版本、渲染器、分辨率、像素比、画质、供电模式。无设备访问时只交付测试脚本与计划，不编造结果。
以固定路线、相机和随机种子测试。预热后采样，说明采样时长；报告帧时间中位数与 P95、卡顿、平均 FPS、内存、绘制调用和主要场景开销。16.67ms 是 60 FPS 的帧预算，不是本项目已达标的证据。
区分 CPU 逻辑/物理瓶颈、GPU 阴影/透明/后期瓶颈和资源加载卡顿；每轮只改一个主要瓶颈，前后保持相同测试条件。
优先尝试实例化、共享材质、减少透明叠加与动态灯光、降低过高 DPR、控制求解迭代、资源预加载。不能只把画面缩成极低分辨率然后宣称优化成功。
Android 需真机持续运行并检查触控、温升和切后台恢复；桌面截图与浏览器手机模拟不能替代真机证据。输出测量原始记录、对比和已知限制。
